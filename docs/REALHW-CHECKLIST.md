# 実機検証チェックリスト

エミュレータでは通っているが、実機では差が出うる項目。上から順に確認すると切り分けしやすい。**書き込み系は必ずコピーしたディスクで試すこと。**

## 起動まで
1. `fdboot.d88` を実フロッピー(2D)に書き、IPL から起動。`bootdev:` で `fd0`(または `fd`)。画面に `init version` が出れば OK。
2. SASI HDD 起動: オプション ROM(各自所持の `FILE.ROM`)経由。ROM は同梱しない。
3. 起動しない場合: 画面が真っ黒 → CRTC/テキスト VRAM 設定(C)、ディスクエラー → FDC タイミング(D)。
4. ブートプロンプト: `hda`/`HDA`/`fd0`/`0 rw`/不正入力(`zzz` で再プロンプト)を試す。起動メッセージが `FUZIX version ...` `Devboot` `256KiB total RAM...` の順に出ること。

## 項目
- A. B5h の自動インクリメント: MMU ページ指定ポートの挙動。エミュレータの想定と実機が違うとユーザープロセスのページが化ける(症状: 起動直後の暴走、sh が起動しない)。
- B. EMM の範囲: 実機の拡張メモリ容量/ページ番号の上限。`free` の値が実機のメモリ構成と一致するか。EMM なしでも起動できるかを併せて確認。EMM の書込み(`emm_wr256`)は OTDR を使うので、データが化けたら通常のループに戻して切り分け。
- C. CRTC/表示: **80 桁 × 25 行**(起動時に IPL の 40 桁から切り替える: CRTC レジスタ 7/8 = 09h/59h、E8h のビット 5 = 1)。実機で画面が崩れる(1 行が 2 つに割れる、桁がずれる)場合は、`devtty_asm.s` の `_mz_video_init` の切り替えを外し、`video.s` の `COLS`、`vt_asm.s` の `VT_RIGHT`、`config.h` の `VT_WIDTH`/`VT_RIGHT` を 40 桁用(40/39)に戻す。キーボード走査は E8h の上位 3 ビットを保つので、ビット 5 は消えない。テキスト VRAM(窓 6)、行・列、スクロール、カーソルも確認する。`vtt`(ESC E、タブ、ESC Y、A/B/C/D、K、J、H、I)を実行して画面を確認。
- D. FDC: モーター on 待ち、ステップ/セトル時間、書き込み後ベリファイ(`fd_verify`)。誤検出するときは `devfd.s` の `call nc, fd_verify` を無効化して切り分け。
- D2. フォーマット(`fdformat`): 実機の Write Track でバイト供給が間に合うか(1 バイト 32 µs)。EIO が出たら Lost Data の疑い。白紙の 2DD で `fdformat /dev/fd1`(読み戻し検証つき)→ `mkfs /dev/fd1 64 1152` → mount → 読み書き。書き込み保護のかかったディスクでも EIO になることを確認。
- D3. セクタ順(インターリーブなし): 連続読み書きが極端に遅い場合は、`devfd.s` の ID 順を表引き(例: 1,9,2,10,...)に変える候補。
- E. SASI のタイミング: REQ/ACK ハンドシェイク、リセット後の待ち時間。タイムアウト時は read/write のエラーが出る。パーティションテーブル("EHSASI"、ブロック 3、優先ブート)の解釈が実機の HDD フォーマットで合うか(`hd: partition at block ...` の表示)。`sasi.s` は 1 バイトにつき状態レジスタ A5h を 1 回だけ読む。失敗するなら 2 回読む実装に戻して切り分け。ACK が自動か、A4h アクセスの後に A5h を読む必要があるかも確認。
- F. キーボード: 全キーのマップ、Ctrl/Shift/GRPH、リピート。`stty` と login での入力を確認。
  - シフトなしの「.」「,」が '.' ',' になること(`echo a.b,c`、`cd ..`)。
  - 記号キーとシフト記号を一通り打つ。実機のキートップ配列が違えば `devtty_asm.s` の `_keytab` / `_keytab_shift` を直す。
  - 未検証: CapsLock、Ctrl+英字・Ctrl+@[\]^_ の制御コード化、キーリピート(初期遅延と間隔)。
- F2. 行編集と制御文字: BS/DEL、Ctrl-U、Ctrl-C(`sleep 100` の中断)、Ctrl-\、Ctrl-D、Ctrl-S/Ctrl-Q、Ctrl-O、長い行(80 桁超)、キュー満杯時にビープが鳴るだけで暴走しないこと。
- G. 割り込み: タイマ。`date`/`uptime`/`sleep` が進むか。
- H. 書き込み系の安全: `fsck` を HDD に対して実行して整合性を確認。ホストでは `tools/fscheck.sh` が通る。
- I. システムコール/ファイルシステム層: `ls`/`cp`/`mkdir`/`rmdir`/`mv`/`ln`/`rm`/`mount`/`umount`/`reboot`/`ps`/`stty` を一通り試す。エミュレータとの差が出るなら I/O 周りだけのはずなので、D/E を先に疑う。
- J. ユーザーメモリ検証(`valaddr`): 不正ポインタ(NULL、u_top 超え、上端をまたぐ)で EFAULT になること。`edge6` で確認。
- K. 書込みの変更点:
  - 新規ブロック確保時(`blk_alloc`)の 512 バイトのゼロクリアは PUSH 方式で、ブロックあたり約 3k サイクル割り込み禁止。キー入力の取りこぼしや時計の遅れが出たら `fs_asm.s` の `ba_zl` ループを 256 バイト×2 に分ける。
  - ディスクフル(ENOSPC=28)と inode 枯渇(ENFILE=23)は `edge4`、`edge5` で確認(edge4 は空きを使い切る)。
  - fork 枯渇(ENOMEM)は `edge7`。

## 既知の注意
- jr によるジャンプテーブルのアドレス依存バグは修正済み。カーネルを変更したら `regress.sh` / `fscheck.sh` で再確認。
- ROM やディスクイメージの入手は各自。リポジトリには含めない。
- upstream の癖(fcntl の F_SETFD/F_DUPFD、flock の shared→exclusive 許可、sync でスーパーブロックのカウンタを書かない)は保持している。
